# Fit/Gap-анализ: цифровой аукцион «Diamond Universe»

**Цель:** определить пробелы (gaps) в функциональности информационных систем и в интеграциях, которые нужно закрыть для перевода аукциона алмазов в онлайн. Сравниваем требуемое целевое состояние (To-Be) с имеющимся (As-Is).

**Обозначения:**
- **НОВ** — новое (требует создания); **СУЩ** — существует (используется как есть или дорабатывается).
- **Fit** — функциональность есть и подходит; **Fit (частично)** — есть, но требует дополнения; **Gap** — функциональности нет или недостаточно.
- *промеж.* — как закрываем за 2 месяца в промежуточном решении; *целевое* — после доработок (~1 год).
- Формат таблицы систем расширен относительно шаблона методички: обязательные поля «новая/существующая» и «комментарий» сохранены, дополнительно вынесены колонки **Тип** (НОВ/СУЩ функциональности) и **Fit/Gap** — для наглядности.

## 1. Системы

Формат: **система (новая/существующая) — функциональность (новая/существующая) — комментарий (что нужно доработать)**.

| Система | Функциональность | Тип | Fit/Gap и комментарий |
|---|---|---|---|
| ИС «Алмазы» (СУЩ) | Отбор алмазов для онлайн-аукциона | **НОВ** | **Gap.** Нет процесса отбора лотов под цифровой канал; *промеж.:* отбор + выгрузка в Excel-ведомость; *целевое:* отдельный модуль отбора. |
| ИС «Алмазы» (СУЩ) | Присвоение идентификаторов ювелирным камням | СУЩ | **Fit.** Используется как есть. |
| ИС «Алмазы» (СУЩ) | Подготовка ведомостей | СУЩ | **Fit (частично).** Ведомости есть; для цифрового аукциона выгружаются в шаблон Excel (*промеж.*). |
| ИС «Алмазы» (СУЩ) | Планирование работ | СУЩ | **Fit.** Используется как есть. |
| ИС «Алмазы» (СУЩ) | План и статус подготовки и проведения аукциона | **НОВ** | **Gap.** Нет план/статус-трекинга; функциональность создаётся в целевом решении. Кейс систему-владельца не называет — размещение в ИС «Алмазы» рядом с планированием работ помечено как допущение; *промеж.:* вручную/Excel; *целевое:* модуль план-факт. |
| ИС «Логистика» (СУЩ) | Перевозка камней по стране и за границу, отправка победителям | СУЩ | **Fit.** Используется как есть. |
| ИС «Логистика» (СУЩ) | Оформление экспортных/таможенных документов на вывоз | СУЩ | **Fit.** Используется как есть — критично для отправки покупателям в Индию/Китай/Бельгию. |
| ИС «Логистика» (СУЩ) | Маршрут «офис → лаборатория → офис» | **НОВ** | **Gap.** Нет этапа доставки в лабораторию и возврата; *промеж.:* заявка вручную; *целевое:* новый тип перевозки + интеграция с «Алмазами». |
| ИС «Аукцион» (СУЩ) | Проведение аукциона, определение победителей торгов | СУЩ | **Fit.** Используется как есть (офлайн-процедура торгов). |
| ИС «Аукцион» (СУЩ) | Онлайн-режим аукциона (приём ставок в системе) | **НОВ** | **Gap.** Онлайн-режима нет; *промеж.:* аукцион на существующей ИС без доработок, ставки удалённых покупателей принимаются вручную через частное облако (допущение); *целевое:* приём ставок в системе. |
| ИС «Аукцион» (СУЩ) | Публикация данных оцифровки для покупателей | **НОВ** | **Gap.** Нет загрузки и отображения аналитики по оцифрованным алмазам; *промеж.:* публикация через частное облако; *целевое:* отдельный внутренний сервис публикации (on-prem, в защищённой зоне для внешнего доступа покупателей). |
| ИС «Бухгалтерия» (СУЩ) | Контракты, актирование и оплата перевозчиков | СУЩ | **Fit.** Используется как есть. |
| ИС «Бухгалтерия» (СУЩ) | Актирование и оплата услуг лаборатории | **НОВ** | **Gap.** Нет контрагента и процесса по лаборатории; *промеж.:* вручную; *целевое:* интеграция с «Лабораторией». |
| ИС «Лаборатория» (**НОВ**, внешняя) | Оцифровка камней (скан, оценка размера, чистоты, флуоресценции в УФ, напряжений/трещин, включений) | **НОВ** | **Gap.** Системы нет в контуре. Внешняя система подрядчика; нужны интерфейсы выгрузки описаний и актов. |
| Частное облако (**НОВ**, внешнее, только промеж.) | Публикация данных покупателям | **НОВ** | Временный канал сбыта. В целевом решении заменяется внутренним сервисом публикации (on-prem). |
| Сервис публикации данных (**НОВ**, только целевое) | Витрина данных оцифровки, публикация лотов, портал ставок покупателей | **НОВ** | **Gap.** Заменяет частное облако и Excel в части публикации. Выделен из ИС «Аукцион» как отдельный on-prem-компонент — архитектурное решение (кейс относит публикацию к ИС «Аукцион»). |
| Excel-реестры по шаблонам (**НОВ**, как «ИС», только промеж.) | Вводные для аукциона: ведомости лотов, описания, акты | **НОВ** | Временная замена доработок ИС. В целевом решении **выводится**. |

## 2. Интеграции

Формат: **интеграция (новая/существующая) — как реализована (автоматически/вручную) — какие данные передаются (новые/существующие)**.

| Интеграция | Реализация | Данные | Комментарий |
|---|---|---|---|

Gap по ИС «Логистика»); *промеж.:* новый маршрут оформляется вручную; *целевое:* добавить параметры маршрута. |
| ИС «Лаборатория» → ИС «Аукцион» | **НОВ** — *промеж.:* **вручную** / *целевое:* **авто** | **НОВ:** цифровое описание и аналитика алмаза | Ключевая новая интеграция. В целевом — выделенный защищённый канал. |
| ИС «Лаборатория» → ИС «Бухгалтерия» | **НОВ** — *промеж.:* **вручную** / *целевое:* **авто** | **НОВ:** акты, счета за оцифровку | Актирование и оплата услуг лаборатории. |
| ИС «Логистика» → ИС «Бухгалтерия» | СУЩ — **авто** | СУЩ: акты и оплата перевозчика | **Fit.** Без изменений. |

## 3. Итоговые пробелы (резюме)

**Главные Gaps, которые закрывает проект:**
- Оцифровка камней — новая внешняя **ИС «Лаборатория»**.
- Онлайн-аукцион и публикация данных — доработка **ИС «Аукцион»**.
- Маршрут в лабораторию — доработка **ИС «Логистика»**.
- Актирование лаборатории — доработка **ИС «Бухгалтерия»**.
- Отбор для цифрового аукциона — доработка **ИС «Алмазы»**.
- План и статус подготовки и проведения аукциона — модуль в **ИС «Алмазы»** (целевое).
- Приём ставок удалённых покупателей — *промеж.:* вручную через частное облако, *целевое:* онлайн-режим **ИС «Аукцион»** (допущение).
- Идентификация камней в лаборатории — сопроводительные ведомости **ИС «Алмазы» → ИС «Лаборатория»** (допущение).
- Триггер доставки победителям — новая интеграция **ИС «Аукцион» → ИС «Логистика»** (допущение).
- Сделка с победителем (контракты, оплата лотов) — интеграция **ИС «Аукцион» → ИС «Бухгалтерия»** (допущение).

**Как закрываются:**
- *Промежуточно* — за счёт Excel-реестров, частного облака и ручных интеграций (быстро, но с рисками ручного труда и зависимости от внешних сервисов).
- *Целево* — за счёт доработки ИС, автоматизации интеграций, выделенных защищённых каналов и переноса облака на инфраструктуру компании.
